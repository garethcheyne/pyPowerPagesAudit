Anonymous global read of a table

contactdataverse:adx

Table permission 'contacts' grants READ with GLOBAL scope on 'contact' to anonymous web role(s) Anonymous. Global scope means every row, not just a signed-in contact's own records. The Web API is enabled for this table, so a visitor can compose their own query at /_api/contacts with fields = emailaddress1,firstname — filtering, paging and column selection are all under their control, not the site's. Referenced by Web page copy 'Child'; Web page copy 'Public API'. Inspect: https://www.contoso-example.com/api, https://www.contoso-example.com/members/detail A visitor can query every row of a table holding personal data. Remove the Global scope or the anonymous binding now. Columns reachable: emailaddress1, firstname. Columns matching personal-data patterns are included: emailaddress1, firstname.

Anonymous global read of a table

productdataverse:adx

Table permission 'products' grants READ with GLOBAL scope on 'product' to anonymous web role(s) Anonymous. Global scope means every row, not just a signed-in contact's own records. The Web API is off and no OData feed is published, so a visitor cannot run their own query. The data is only reachable where a page renders it, so the real exposure is whatever those pages choose to show. No Liquid template, page copy, entity list or page script in this site was found to reference the table, so nothing appears to render it today. Treat the permission as dormant configuration: it grants access that only becomes live when someone adds a page that uses it. Nothing renders it and nothing can query it, so it is granting access no-one is using. Remove the permission to keep the anonymous role minimal. Columns reachable: (no Web API site setting; exposure depends on another channel).
